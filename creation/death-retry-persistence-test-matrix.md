# Death, Retry, Persistence, and Replayability Test Matrix

This instrument finds the smallest reset loop in which death creates consequence, the next attempt carries a usable distinction, variation remains learnable, and persistence never substitutes accumulation for change.

## Build one instrumented reset loop

- three connected spaces: preparation, learned traversal, and unresolved pressure;
- one transient resource, one recoverable resource, one durable unlock, one world mutation, and one knowledge entry;
- one fixed encounter and one seeded recombination of known components;
- checkpoints before the run, before solved traversal, and before unresolved pressure;
- one safe recovery window and one scarcity branch;
- exact state manifests before death, after death, after retry, and after reload;
- exact seed, generator inputs, rule versions, and mutation list;
- optional practice, journal, reduced-repetition, and accessibility controls;
- crash injection during death commit and during checkpoint restoration.

## Instrument the circuit

```text
enter with declared state
→ spend, risk, search, route, and fight
→ receive readable success or failure evidence
→ partition transient, recoverable, durable, world, and knowledge state
→ commit death atomically
→ restore from a declared retry boundary
→ compare the new state with the prior attempt
→ name the retained distinction
→ change one decision or execution
→ reproduce or vary the run under recorded rules
→ stop when no unresolved distinction remains
```

Death is not progression by itself. A rising counter, currency total, or completion percentage qualifies only when it changes a later decision under a declared rule.

## Required measurements

| Area | Minimum record |
|---|---|
| Transition | death cause, timestamp, pre-state hash, reset manifest, post-state hash |
| Partition | transient, recoverable, durable, world mutation, witnessed knowledge |
| Retry | checkpoint, restoration inputs, load time, time to unresolved decision |
| Learning | prior hypothesis, evidence, changed hypothesis, next changed action |
| Variation | seed, component identities, mutations, compatibility, solvability |
| Pressure | resources by room, sources, sinks, safe window, unrecoverable state |
| Narrative | witnessed fragment, cycle context, uncertainty retained |
| Accessibility | assistance, repeated-content reduction, meaning and timing preserved |

## Test passes

1. **Partition proof:** kill the player after acquiring one item in every state category. Compare declared, actual, displayed, saved, and reloaded state.
2. **Atomicity breaker:** interrupt the death write after every individual operation. Recovery must yield either the complete parent or complete successor—never a mixture.
3. **Checkpoint comparison:** run from all three boundaries. Measure time to the unresolved decision, restored resources, tension, and new learning.
4. **Solved-content subtraction:** remove the learned traversal from retry. If challenge disappears, identify the real dependency; otherwise stop forcing its repetition.
5. **Knowledge witness:** after every attempt, require one witnessed distinction and one proposed change. Record `NO_NEW_DISTINCTION` honestly.
6. **Retention subtraction:** disable each durable value independently. Retain only values whose absence changes a later decision, interpretation, route, or capability.
7. **Seed replay:** reproduce every accepted and failed run from its receipt. Layout, offers, enemies, mutations, and required resources must agree.
8. **Rule continuity:** move known components into new combinations. Players should recognize identity and transfer valid counters before mastering the new composition.
9. **Invalid-seed breaker:** inject incompatible components, missing recovery, blocked routes, and impossible resource demand. Generation must reject them deterministically.
10. **Pressure waveform:** plot danger, resource margin, cognitive load, and recovery across the route. Constant maximum pressure and constant safety both fail.
11. **Journal boundary:** compare witnessed-only, hint-assisted, and solution-filled records. Persistence must not present unseen knowledge as player discovery.
12. **Long-loop exhaustion:** repeat beyond novelty. Track when attempts stop producing distinctions and whether the system changes, concludes, or wastes time.

## Player questions

1. What exactly was lost, recoverable, and retained?
2. Why did you die?
3. What will you do differently now?
4. Which earlier section are you still learning?
5. Which earlier section are you only repeating?
6. Did the new run change arrangement, rules, or both?
7. Which knowledge transferred correctly?
8. Did scarcity change a decision or merely slow you down?
9. Did the safe window create relief or remove danger?
10. What uncertainty remains?

Preserve player explanations separately from designer intention, state counters, completion time, and win rate.

## Stop conditions

Do not add more currencies, unlock trees, death penalties, procedural rooms, checkpoints, or run modifiers while any remain:

- declared and actual reset partitions disagree;
- death or restoration can commit partially;
- the player cannot predict which state category an object occupies;
- retained progression changes no later decision;
- dying grants unseen routes, counters, schedules, or identities as facts;
- solved content dominates time before the newest unresolved rule;
- a checkpoint changes the resources or dependencies of the tested decision;
- repeated attempts produce no new distinction and the loop continues unchanged;
- variation silently changes a known component rule;
- a failed seed cannot be reproduced exactly;
- an accepted seed has no viable route, counter, or minimum resource supply;
- scarcity changes only waiting, searching, or duration;
- one mistake creates an unrecoverable state long before the player can recognize it;
- permanent growth erases survival pressure or turns every later run into cleanup;
- average completion hides one deterministic impossible sequence;
- accessibility or repetition controls silently grant success or rewrite persistence.

## Selection rule

Retain the smallest reset partition, retry boundary, variation set, and pressure waveform for which every death leaves a readable consequence, every continued attempt tests a remaining distinction, every run is reproducible, and the loop stops or transforms when comparison yields nothing new.
